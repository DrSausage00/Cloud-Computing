# Storage Layer

## Overview

The project uses MinIO as an S3-compatible object store.

Business data is stored in the `mes-data` bucket.
Spark Structured Streaming checkpoints are stored separately in
the `spark-checkpoints` bucket.

## Storage layout

mes-data/
- bronze/machine-events/
- silver/machine-metrics/

spark-checkpoints/
- kafka-to-bronze/
- machine-aggregation/

## Bronze Layer

The Bronze layer contains the normalized machine events received
from the Kafka topic `machine-events`.

The original CSV, JSON and pipe-separated source formats are already
normalized by the ingestion component before they are sent to Kafka.
Therefore Bronze contains the canonical Kafka events rather than the
original source strings.

Location:

`s3a://mes-data/bronze/machine-events`

Partitioning:

`event_date`

## Silver Layer

The Silver layer contains processed machine metrics generated by
the stream-processing component.

This includes window aggregations, stateful information, enrichment
and limit checks.

Location:

`s3a://mes-data/silver/machine-metrics`

Partitioning:

`event_date`

## Table format

Delta Lake is planned as the table format.
The physical data files are stored as Parquet.

Delta is used to provide a table abstraction, schema handling,
transaction metadata and versioning on top of the object store.

## Partitioning decision

Both business tables are partitioned by `event_date`.

Historical MES queries commonly operate on time ranges. Date
partitioning allows irrelevant partitions to be skipped.

The data is deliberately not partitioned by `machine_id`, because
a production MES can contain many machines and this could create
a large number of small partitions.
